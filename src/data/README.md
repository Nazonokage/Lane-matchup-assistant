# Live data contract

The Draft Helper is built from the files below. Editing `archive/` does not change the app.

| File | Purpose |
| --- | --- |
| rosters.json | Separate official roster snapshots and source URLs for each game |
| championGuides.js | Champion plans, supported roles, damage categories and base traits; explicit game overrides |
| counterplay.js | Opponent advice and key resource/cooldown windows |
| draftProfiles.js | Reviewed trait corrections and role-specific scoring context |
| draftRules.js | Active declarative rules for enemy duos, partner setup and composition plans |
| draftInteractions.js | Dated, source-linked plans for specific enemy threats across roles; one bounded score bonus |
| strategy.js | Named interactions, duo pairings and role plans |
| meta.json | Patch summaries, dates and confidence statements |
| pcKitReferences.json | Pinned Riot PC kit links and short attributed tips; never WR evidence |
| dataset.json | Generated by `npm run build:data`; do not hand-edit |

Run `npm test` after data edits. It validates source schemas, references, scoring and game isolation. Run `npm run audit:data` for a per-role coverage report. Coverage of a champion profile is not evidence of a reviewed counter matchup.

Rules use named scopes (`enemySupport`, `enemyBot`, `direct`, `partner`, `allies`, `enemies`) and known traits. `candidateAll` requires every trait; `candidateNone` excludes matching traits; `enemyAny` matches at least one. `minimum` counts matched champions. A zero delta supplies advice only. At most one positive and one negative bot archetype rule can score, avoiding repeated rewards for related traits.

Support economy suppresses carry-damage, wave-clear and split-pressure assumptions. Farming roles preserve their champion profile. Item-dependent damage, current wave states, skill, lane priority and exact build choices remain unknown.

The helper ranks only candidates with at least one scored signal. A zero total can reflect offsetting signals; it differs from no evidence. Negative totals are cautions. Empty evidence is never converted into a neutral matchup or alphabetically invented recommendation.

## Audit findings (2026-10-25)

- The previous lane JSON files and condition-string rules were not active. They contained obsolete patch labels, broad counter claims and conditions mixing enemy and ally identity. Preserved in `archive/` for reference, not restored into live scoring.
- Removed false Amumu knockup setup; expanded missing airborne tags and corrected role-aware damage assumptions. Broad damage categories remain build-dependent.
- PC Corki now has a physical damage profile; WR keeps its mixed profile. References: [PC Corki](https://www.leagueoflegends.com/en-us/champions/corki/), [WR Corki](https://wildrift.leagueoflegends.com/en-us/champions/corki/).
- Bot archetype rules now inspect the enemy support and duo. These explain conditional tools and risks, not measured winning matchups.
- Role coverage and named matchup coverage differ greatly. In particular, most solo-lane and WR matchups still lack named interactions. Use the generated audit report to choose the next research targets.
- No live rank/region sample sizes, win rates, rune builds or exact item timings are available. Those must be sourced separately before they can drive rankings.

## Progressive draft recommendations (2026-10-26)

The selected direct opponent now supplies conditional lane or jungle options even when no named pair has been reviewed. Fifteen additional rules cover opponent control, mobility, wave pressure, durability, scaling, side pressure and the enemy jungler. Solo-lane archetype scoring is capped to one positive and one negative direct-opponent signal; the enemy-jungle adjustment remains separate. Adding more picks reranks the available champions, not a permanent elimination filter. Equal scores remain tied, with alphabetical presentation. No win-rate ranking is implied.

Archive review: `Midlane.json` and `JglRole.json` supplied research prompts, not trusted counters. Ahri–Diana was rewritten as a conditional Charm timing opportunity after checking Riot PC and WR kit descriptions. Claims such as Akshan having his shield on W, Ahri revealing Akali through shroud, and Wild Rift post-6 jungle timing were not imported. Active total: 40 named interaction records, 35 conditional rules and 13 cross-role records.

Each recommendation card now shows its draft rationale, champion plan, direct-opponent advice and risk. Expanded advice includes the selected opponent’s cooldown, partner coordination, purchases and objectives. General role primers are collapsed below results. Tests cover every direct opponent in Mid, Baron and Jungle in both games, plus Lux mid followed by Vi jungle to verify changed scores, choices and slot-specific explanations.

## Cross-role partial-draft fix

Five bounded team-threat rules now consider enemy picks outside the selected direct matchup. This fixes empty Top/Jungle results for an enemy mid such as Lux or an enemy ADC such as Miss Fortune. At most one team-threat rule scores per candidate, and solo-lane jungle adjustments stay separate. These are conditional teamfight options, not named lane evidence. Regression tests reproduce both games and verify that hidden own-role selections do not generate recommendations. Current rule total: 40.

Game, lane and draft choices are now in-memory only. Startup removes only Lane Ledger’s five retired preference keys; it never clears unrelated storage.
